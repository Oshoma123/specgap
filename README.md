# SPECGAP

**Status:** DRAFT v0.1 (unverified; pipeline validated only on a synthetic fixture, not real data) | **Maintainer:** Oshoma Erumiseli, [ORCID 0009-0004-3813-4650](https://orcid.org/0009-0004-3813-4650) | **License:** code [MIT](LICENSE), data [CC BY 4.0](LICENSE-DATA)

SPECGAP is an open engine for assessing the coverage of public MS/MS spectral
libraries against public natural-product structure databases. It cross-matches
natural-product structure sets (**LOTUS**, **COCONUT**) against the open
spectral-library layer (**GNPS**, **MassBank**, **MoNA**) and reports two
things: **structural coverage** (what share of known NP structures have a
matching spectrum anywhere) and **name-recoverability** (what share of
spectral-library entries can be correctly tied back to a natural-product
identity by name). Founded September 2026.

## ⚠️ Before you trust any number here

This repository currently ships **synthetic fixture data only**
(`data/raw/fixtures/`, generated by `code/00_make_fixture.py`). It exists to
prove the pipeline runs correctly end-to-end — every script, join, QA check,
and figure has been executed and works — but **none of the coverage or
name-recoverability numbers in `data/processed/`, `paper/figures/`, or the
manuscript drafts are real audit results.** The build environment this
repository was first assembled in has no outbound network access, so the
real multi-million-record bulk downloads from LOTUS/COCONUT/GNPS/MassBank/MoNA
could not be pulled. See `docs/BUILD_SPEC.md` for the full explanation.

**To get real numbers:** delete `data/raw/fixtures/`, run
`code/01_fetch.py --all` on a machine with network access (it points at the
real bulk-download pages and logs provenance), place the downloaded files
under `data/raw/<source>/` in the same column shape as the fixture CSVs
(see `docs/CODEBOOK.md`), then re-run `code/02_build.py` through
`code/04_figures.py --final`.

## Tests

`tests/` has unit tests for the matching/normalization logic (including one
real, verified COCONUT record — see `docs/REAL_RECORD_EXAMPLE.md`) and an
end-to-end pipeline test. Run with `pytest tests/ -v`; CI
(`.github/workflows/tests.yml`) runs this automatically on every push once
the repo is on GitHub.

## Run it

```
pip install -r requirements.txt

# Fixture run (works offline, proves the pipeline):
python code/00_make_fixture.py
python code/02_build.py
python code/03_qa.py
python code/04_figures.py          # drop --final to keep the DRAFT watermark

# Real run (requires network):
python code/01_fetch.py --all      # follow the printed instructions per source
python code/02_build.py
python code/03_qa.py
python code/04_figures.py --final
```

A stranger should be able to run these from this README alone and reproduce
`data/processed/` exactly, on either the fixture or real data.
